Signal chain map for a small church

Guide 3 of 3 core guides. One path, in order, in plain language.

When a microphone goes silent or a hum appears five minutes before the service, panic makes troubleshooting slower. A signal chain map fixes that. It is just the path sound takes, in order, from the person speaking to the people listening, in the room and online.

Learn the path once and most problems get smaller. You stop guessing and start checking, one stage at a time.

The map

Source (voice, instrument) -> Microphone or DI box -> Cable, or wireless transmitter and receiver -> Stage box or console input -> Console channel: gain, EQ, fader -> Console outputs: main, monitors, stream bus -> Amplifiers and speakers (room) -> Streaming computer or encoder (online)

Some churches run parts of this path over a digital network such as Dante, where one network cable carries many channels between a stage box and the console. The order is the same. Only the cable changes.

Each stage, in plain terms

1. Source

The voice or instrument itself. A quiet source, a singer far from the microphone, or a keyboard with its volume low will cause problems that no console setting can fully fix. Start here: is the source actually producing sound at a normal level?

2. Microphone or DI box

The microphone picks up the source. A DI box connects an instrument, such as keys or an acoustic guitar, to the system cleanly. Check that the right microphone is on, that a wireless handheld has fresh batteries, and that the microphone is close enough to the source.

3. Cable, or wireless link

Cables fail more often than consoles do. A crackle when the cable moves means replace the cable. For wireless, including Shure wireless systems, check that the transmitter and receiver are on the same frequency or channel, that the receiver shows signal, and that the antennas have a clear view of the stage.

4. Console input and channel

The signal lands on a console channel. Check the basics in order: correct input selected, gain set well, channel not muted, fader up, and the channel assigned to the main output. Many silent channel problems are a mute, a wrong input patch, or a fader that never came up.

5. Console outputs

One console usually feeds three different listeners: the room through the main output, the stage through monitor outputs, and the stream through its own bus. A problem can live in only one of these. If the room sounds fine but the stream is silent, the fault is in the stream path, not the channel.

6. Amplifiers and speakers

The last step for the room. If the console meter shows signal but the room hears nothing, check amplifier power, speaker connections, and any processor or mute between the console and the speakers.

7. Streaming computer or encoder

For online listeners, the chain continues: console stream output, cable or USB or Dante connection, streaming software input, and the platform. Check each handoff. The most common fault is simple: the streaming software is listening to the wrong input.

How to troubleshoot with the map

Work the path in order and change one thing at a time.

  1. Name the problem precisely. One channel, or everything? Room, monitors, stream, or all three?
  2. Compare with a channel that works. Swap the cable first, then the microphone if needed. If the problem moves with the cable, you found it.
  3. Check the meters. Signal at the channel but not at the output points downstream. No signal at the channel points upstream, toward the cable, microphone, or source.
  4. Check the simple state at each stage: power on, not muted, connected, correct input.
  5. Write down what fixed it. The next volunteer should not have to solve the same fault from scratch.

Checklist: when something stops working

  • Say exactly what is affected: one channel or all, room or stream or both
  • Check the source is producing sound at a normal level
  • Check microphone power, batteries, and distance from the source
  • Swap the cable with a known good cable
  • For wireless, check receiver signal and that transmitter and receiver match
  • Check the console channel: input, gain, mute, fader, output assignment
  • Check the specific output path that is failing, room, monitor, or stream
  • For stream faults, confirm the software is set to the correct input
  • Log the fault and the fix in a notebook at the sound desk
